# 回响市集 EchoMarket · 六人分工

> 仓库：`https://github.com/Aznobin/echo-market.git`
> 汇报形式：**每人各自汇报**，因此设一名专职 PPT 负责人统一收口
> 硬要求：老师只看量化数据；每人要能拿出 git 提交图

## 一、分工总览

| # | 角色 | 核心交付物 |
| --- | --- | --- |
| 1 | 需求文档 | 需求文档 docx（功能结构图、用例图、流程图、数据库设计图） |
| 2 | 开发文档 | 开发文档 docx（README 整理、当前进度）+ `assets` 清单 |
| 3 | PPT（专职） | 汇报 PPT：现有进度 + 分工状态 + 量化数据 |
| 4 | 素材 | 按 `assets` 清单收集素材包 |
| 5 | 开发 A | 代码 + git 提交记录 |
| 6 | 开发 B | 代码 + git 提交记录 |

## 二、各角色细则

### 1. 需求文档

- 先 `git pull`
- 图要齐：**功能结构图、用例图、数据库设计图、流程图**
- 数据库设计图统一字段口径：`status`（int）、`create_time`（timestamp）、`update_time`（timestamp）
- 技术框架写清：Servlet + JSP、Model2 MVC、c3p0 + commons-dbutils
- 交付：需求文档 docx

### 2. 开发文档

- 先 `git pull`
- 整理 `README.md`：项目介绍、技术架构、目录结构、请求流程
- 记录当前流程与进度：已完成 / 进行中 / 待开始
- **数据库表名由本角色定**
- **负责产出 `assets` 清单**（文件名 + 用途 + 来源），供素材角色按单收集
- 交付：开发文档 docx + `assets` 清单

### 3. PPT（专职）

- 收齐各角色的原始材料，整理**现有进度**与**分工状态**
- 量化数据是重点（老师只看这块）：功能点数、用例数、页面数、表数与字段数、提交数
- 每人各自汇报 → PPT 要预留每个人的板块
- 交付：汇报 pptx

### 4. 素材

- 按 `assets` 清单逐项找，不自己乱加
- 目录与命名一律英文（`assets/`、`icon/`、`screenshot/` 这类），不用中文名
- 交付：素材包

### 5. 开发 A / 6. 开发 B

- 想写哪块就写哪块，不硬切模块，但两人别撞同一块
- 按下面的 git 规范开工
- 交付：代码 + git 提交记录

## 三、Git 规范

| 分支            | 用途                                       |
| ------------- | ---------------------------------------- |
| `main`        | 稳定版，给老师看的                                |
| `dev`         | 合并线，做合并测试                                |
| `feature/xxx` | 模块线：`login`、`order`、`frontend`、`admin` … |
| `chore/xxx`   | 环境配置线：`config`、`database` …              |

`feature/*` 与 `chore/*` 底下的具体线还没配，谁开谁建。

**提交纪律**：

- 每人每 2～3 天一次提交，**改一个字提交也算**
- 提交人名字必须真实，老师会翻 commit 记录
- 提交信息写清做了什么，不写 `update` / `test` 这类水词

## 四、红线

- 每人最后都要能拿出 git 提交图
- 量化数据必须能答上来源
- 交付物避免 AI 痕迹：措辞、排版要像各自手写的，不要模板化套话
- 没实现的功能只能写「计划实现」

## 五、待定

- 数据库表名：由开发文档负责人定
- 模块划分：自由认领，避免撞车
